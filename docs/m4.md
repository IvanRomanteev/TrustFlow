## What M4 delivers

Package `src/trustflow/evaluation/` (no changes to accepted engine,
persistence, API or frontend code):

- `cases.py` — versioned registry (`trustflow-eval-33-v1`) of all 33
  maintained cases with stable IDs identical to the pytest set,
  categories, critical-safety flags and a SHA-256 `dataset_digest()`.
  A drift-guard test fails if the registry and the pytest set diverge.
- `runner.py` — one-command offline runner. Each case builds a fresh
  engine/registry/ledger (isolation, order independence) and executes
  through the normal create/approve/resume flow. Observed outcomes,
  transaction counts, usage and traces are read back from the
  authoritative run record, ledger and audit log — M4 creates no
  alternate source of truth and no execution path of its own.
- `schemas.py` — versioned (`1.0`) Pydantic result schema. `null`
  means unknown/not measured; zero means measured zero. Fake-provider
  token usage stays `null` and cost stays `null`; nothing is invented.
- `metrics.py` — safety, outcome, evidence, performance and usage
  metric families, each with an explicit denominator in
  `metrics.definitions`. Latency percentiles always carry `n`; p95 at
  this sample size is descriptive only. No single opaque score.
- `trace.py` — per-run trace export built only from `AuditLogger`
  events. `trace_id == run_id`, so retries, resumes and recovery
  continue one trace. Stage mapping covers run_created, planning,
  policy, retrieval, approval, execution, deterministic/semantic
  verification and persistence/recovery. Details are already redacted
  by the audit logger and pass through `redact_any` again on export;
  a run with no audit events exports an empty trace, never a
  fabricated one.
- `ablation.py` — two shadow/diagnostic comparisons (below).
- `report.py` — atomic JSON/CSV/Markdown/trace/manifest writers.
  Write failures raise; they are never silently ignored.
- `__main__.py` — CLI (below) with enforceable exit codes.

### CLI and gates

```powershell
.\.venv\Scripts\python.exe -m trustflow.evaluation --out artifacts/m4-eval --repeat 2 --ablations
```

Exit codes: `0` all cases pass and zero safety violations; `1` case
failures; `2` critical safety violations; `3` harness errors; `4`
verdicts differ across `--repeat` runs. A denied high-risk intent is
an expected policy rejection and counts as a successful safety
outcome, not a model failure. Safety violations detected per case:
`unexpected_ledger_mutation` (more committed transactions than the
case allows), `false_completed` (COMPLETED with a failed verification
report), `mutation_on_failed_workflow`, and
`invalid_canonical_evidence_accepted` (forged span accepted).

### Usage and cost accounting

Usage is aggregated from the authoritative `run.llm_calls` records:
logical calls are distinct `(purpose, attempt)` pairs, transport
attempts are the flat record count, so retries are never
double-counted and never inflate the logical count. Cost is reported
only when both token counts are known and the model has a configured
price in the existing `PRICING_PER_MILLION`; otherwise
`estimated_cost_usd` is `null` (unknown, not zero, not free). In fake
mode tokens are unknown, so cost is `null` and
`missing_usage_rate` is reported explicitly. No pricing was invented
for M4; the pre-existing table is reused as-is.

### Ablations (offline, fake provider)

- **A — verifier diagnostics.** Deterministic-check verdicts are
  compared with the full deterministic+semantic verdicts on identical
  normally-executed runs. Diagnostic read only: no verification is
  disabled on any mutating path. Result at the M4 candidate run:
  18/18 comparable cases agree; the remaining runs end before a
  verification report exists (planning/policy failures).
- **B — retrieval context on/off.** Identical cases with the advisory
  retriever wired vs omitted (M1 wiring); policy, approval and
  verification are unchanged in both. Result: 23/24 terminal statuses
  consistent. The single difference,
  `mandatory_evidence_workflow_completes_with_citations`, correctly
  FAILS without a retriever because no canonical evidence can be
  attached — the mandatory gate failing closed, not a regression.
  Mean evidence spans per case drop from with-retriever to 0 without.

Both are fake-provider pipeline diagnostics. They do not establish
real model accuracy; the semantic reviewer is scripted in fake mode.

## Limitations and deferred items

- Trace spans are derived from audit events (stage-level), not
  fine-grained in-engine spans; no OpenTelemetry/Langfuse (optional
  per kickoff, no immediate benefit offline).
- Live-model evaluation and real Meta pricing are out of scope and
  require explicit approval for paid calls.
- Latency numbers are single-machine fake-mode timings for regression
  comparison only.
- Generated artifacts under `artifacts/` are git-ignored; the
  reproducibility manifest records the dataset/verdict digests.

## Remediation round 1 (post independent review)

The first candidate (`3ea23cd`) was **BLOCKED** by the independent
review with six P1 findings (F1–F6) and two P2 (F7–F8). Remediation
on `m4/acceptance-remediation-r1`, without touching accepted M1–M3
code or the published candidate:

- **F1 — full semantic coverage.** The runner now executes the
  maintained assertions: retrieval top-document **and score > 0**;
  pre-approval lifecycle (pause present, ledger empty, no snapshot,
  retrieval evidence attached); post-approval ledger snapshot and
  ledger citation; mandatory policy+ledger citations; exact span
  text slice equality plus integrity and relevance as separate
  checks. The drift guard compares the registry with the maintained
  M1 fixtures field-by-field (steps, expected status, approval flag,
  tx count), and `assertion_contract_digest` in every manifest hashes
  the maintained eval test files plus the registry, so a semantic
  assertion change alters the published provenance. Limitation: the
  digest records that assertions changed; the pytest parity test is
  what enforces equivalence.
- **F2 — credible safety metrics.** New detector
  (`evaluation/safety.py`) validates authoritative run/plan/approval/
  verification/evidence/ledger data and re-runs the independent
  deterministic Verifier as an oracle. Labels: `missing_verification`,
  `false_completed`, `inconsistent_verification_report`,
  `ledger_state_inconsistent`, `duplicate_committed_operation`,
  `unexpected_ledger_mutation`, `mutation_on_failed_workflow`,
  `unauthorized_approval_acceptance`, `invalid_mandatory_evidence`,
  `invalid_canonical_evidence_accepted` (forged-span acceptance only;
  rejecting a valid span is an ordinary failure). Metrics publish the
  applicable population and list unmeasured properties (crash/restart
  recovery, approval races — covered by retained M1–M3 tests)
  explicitly instead of as zeros.
- **F3 — per-record usage/cost.** Cost is computed per usage record
  with that record's model; the total is `null` whenever any record
  is incompletely tokenized or unpriced. `partial_known_cost_usd`
  (fully priced records only), per-case `models`, `unpriced_records`
  and `unknown_token_records` are reported separately. Mixed-model
  runs are never attributed to the first record's model.
- **F4 — sanitized errors.** Harness exceptions are published only as
  exception class plus redacted, bounded message
  (`evaluation/errors.py`); report writers redact defensively; the CLI
  prints sanitized JSON errors without tracebacks. Trace detail
  exports are size/depth bounded.
- **F5 — CLI lifecycle.** Inputs validated first; all repeats execute
  and every repeat verdict is retained in `repeats.json`; artifacts
  are written to a staging directory, JSON-validated, then published
  by rename with `COMPLETE.json` in the staged set. A failed run
  removes staging and never overwrites a previously published
  successful report. Documented precedence: 2 safety > 3 harness >
  4 reproducibility > 1 assertion > 0 pass; 64 for CLI usage errors.
- **F6 — pinned configuration.** Offline settings are pinned by
  explicit constructor values (ambient `TRUSTFLOW_*` cannot change
  the evaluated safety path; verified against the reviewer's X01
  probe: effective threshold stays 1000.0). The manifest publishes
  the allowlisted `effective_config`, `config_digest` (covering
  pinned settings, selected case IDs, dataset and assertion-contract
  digests), so identical provenance now implies identical evaluated
  configuration. Subset runs are identified by the digest of the
  selected cases.
- **F7 — invalid inputs.** Empty suites, duplicate case IDs and
  unknown kinds raise controlled `ValueError`s (harness exit 3);
  unknown kinds are never dispatched to another probe; invalid
  `--repeat` values exit 64 before any evaluation.
- **F8 — known zero.** Measured-zero token sums aggregate as `0`;
  `None` only when no known values exist, at record and aggregate
  level.

Validation after remediation: full pytest **321 passed** (299

## Remediation round 2 (targeted closure of R1-F2, R1-F4, R1-F5)

The R1 candidate (`e15b095`) closed F1/F3/F6/F7/F8 (independently
verified FIXED) but remained BLOCKED on three P1 findings. Round 2 on
`m4/acceptance-remediation-r2` closes them, evaluation layer only:

- **R1-F2 — complete constituent safety validation.** The detector
  now checks: ledger conservation for **every** terminal state, not
  only COMPLETED runs (S15: FAILED workflow with a silent +1 balance
  mutation and zero transactions is detected); semantic constituent
  consistency (S11: aggregate `passed=True` with a semantic FAIL
  verdict is `inconsistent_verification_report`); approval
  authorization via the accepted `HumanApprovalService.is_approved`
  oracle — exact APPROVED decision bound to the executed snapshot
  hash/version (S12 REJECTED record, S13 foreign plan hash both yield
  `unauthorized_approval_acceptance`); and canonical citation
  validation of mandatory spans against the authoritative corpus
  document or ledger snapshot (S14: foreign `source_id` yields
  `invalid_mandatory_evidence` even when quote/hash are
  self-consistent). S01–S10 classifications are preserved; the normal
  33-case suite still detects zero violations.
- **R1-F4 — publication-boundary sanitization.** One defensive
  boundary (`sanitize_payload` in `evaluation/errors.py`) produces a
  sanitized, bounded presentation copy of every published payload:
  structured results, summary/metadata, CSV, Markdown, traces,
  timelines, manifest, ablations and completion metadata. Credential
  mapping keys and secret-looking strings are redacted recursively,
  strings/collections/depth are bounded, unsupported custom objects
  become a fixed placeholder rather than their `str()`. The
  credential-key policy is deliberately narrower than a substring
  "token" match so usage measurements (`input_tokens`, …) survive
  unchanged. All formats and the published verdict digests derive
  from the same finalized sanitized report copy; authoritative
  records are never mutated. The reviewer's `boundary_payload` and
  `ablation_payload` subprocess probes now find zero marker matches
  in every artifact.
- **R1-F5 — precedence and preservation.** Safety findings are
  accumulated as each repeat completes and the documented precedence
  (2 > 3 > 4 > 1 > 0) is applied in the exception handler too: a
  writer, ablation or later-repeat failure after an observed safety
  violation exits 2 and preserves the finding in a sanitized failure
  summary (never a false completion marker). Publication is
  transactional with attempt-unique staging directories (only their
  owner removes them; unrelated pre-existing staging content is never
  deleted). `COMPLETE.json` records `gate_exit_code` and means only
  "this attempt was fully published", not gate PASS. A non-pass
  attempt never replaces a previous completed publication: it is
  published separately to `<name>.failed-<attempt>` with its own
  source SHA and attempt identity.

## Remediation round 3 (R2-F4a, R2-F4b, R2-F5)

Parent R2 candidate ``ba4d1997409461cba597d9028200634189a0d740`` was
independently BLOCKED on three residual defects, closed here in the
evaluation layer only:

- **R2-F4a - mapping keys.** ``sanitize_payload`` now sanitizes mapping
  keys with the same credential policy as values: secret-bearing keys
  (for example an ``Authorization Bearer ...`` header used as a key)
  are redacted, label-like identifiers such as ``input_tokens``,
  ``output_tokens`` and ``token_budget`` are preserved as field names
  (their values are still redacted when credential-like), unsupported
  key objects become ``<unsupported-key>`` without ever calling their
  ``__str__``/``__repr__``, and keys that collide after sanitization
  are kept distinct with an explicit ``<collision-N>`` suffix instead
  of silently overwriting. Length/depth/item bounds and authoritative
  object immutability are unchanged.
- **R2-F4b - unified safe stdout.** The CLI builds every published
  value, including the final stdout JSON and ``COMPLETE.json``, from
  the single finalized sanitized report copy and passes the complete
  stdout payload through ``sanitize_payload``. No raw run metadata is
  read after finalization. Critical provenance (``config_digest``,
  ``dataset_digest``, ``assertion_contract_digest``, ``git_sha``) is
  validated as hex digests; malformed provenance is rejected with a
  controlled harness error (exit 3, sanitized, unpublished) instead of
  being published as a successful reproducibility claim. Stdout,
  manifest and COMPLETE digests therefore agree on valid runs.
- **R2-F5 - completed-repeat evidence.** Each completed repeat now
  immediately records a bounded sanitized evidence entry: repeat
  index, attempt id, candidate Git SHA, verdict/config/dataset
  digests, counts, per-case failed/safety findings (case id, safety
  labels, workflow/trace identity) and trace ids/digest. On a later
  repeat, writer or ablation failure the CLI retains those records,
  applies the existing precedence (2 safety > 3 harness > 4
  reproducibility > 1 assertion > 0; 64 for input errors), writes a
  separately identified ``<name>.failed-<attempt>/FAILED_ATTEMPT.json``
  (plus bounded ``failed-traces.json``) when writing is possible, and
  always emits the same critical findings in the bounded sanitized
  stdout/stderr fallback. No COMPLETE marker is created for an
  incomplete attempt, the failure summary never claims PASS, and a
  previous successful publication is never replaced.
