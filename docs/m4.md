## What M4 delivers

Package `src/trustflow/evaluation/` (no changes to accepted engine,
persistence, API or frontend code):

- `cases.py` — versioned registry (`trustflow-eval-33-v1`) of all 33
  maintained cases with stable IDs identical to the pytest set,
  categories, critical-safety flags and a SHA-256 `dataset_digest()`.
  A drift-guard test fails if the registry and the pytest set diverge.
- `runner.py` — one-command offline runner. Each case builds a fresh
  engine/registry/ledger (isolation, order independence) and executes
  through the normal create/approve/resume flow. Observed outcomes,
  transaction counts, usage and traces are read back from the
  authoritative run record, ledger and audit log — M4 creates no
  alternate source of truth and no execution path of its own.
- `schemas.py` — versioned (`1.0`) Pydantic result schema. `null`
  means unknown/not measured; zero means measured zero. Fake-provider
  token usage stays `null` and cost stays `null`; nothing is invented.
- `metrics.py` — safety, outcome, evidence, performance and usage
  metric families, each with an explicit denominator in
  `metrics.definitions`. Latency percentiles always carry `n`; p95 at
  this sample size is descriptive only. No single opaque score.
- `trace.py` — per-run trace export built only from `AuditLogger`
  events. `trace_id == run_id`, so retries, resumes and recovery
  continue one trace. Stage mapping covers run_created, planning,
  policy, retrieval, approval, execution, deterministic/semantic
  verification and persistence/recovery. Details are already redacted
  by the audit logger and pass through `redact_any` again on export;
  a run with no audit events exports an empty trace, never a
  fabricated one.
- `ablation.py` — two shadow/diagnostic comparisons (below).
- `report.py` — atomic JSON/CSV/Markdown/trace/manifest writers.
  Write failures raise; they are never silently ignored.
- `__main__.py` — CLI (below) with enforceable exit codes.

### CLI and gates

```powershell
.\.venv\Scripts\python.exe -m trustflow.evaluation --out artifacts/m4-eval --repeat 2 --ablations
```

Exit codes: `0` all cases pass and zero safety violations; `1` case
failures; `2` critical safety violations; `3` harness errors; `4`
verdicts differ across `--repeat` runs. A denied high-risk intent is
an expected policy rejection and counts as a successful safety
outcome, not a model failure. Safety violations detected per case:
`unexpected_ledger_mutation` (more committed transactions than the
case allows), `false_completed` (COMPLETED with a failed verification
report), `mutation_on_failed_workflow`, and
`invalid_canonical_evidence_accepted` (forged span accepted).

### Usage and cost accounting

Usage is aggregated from the authoritative `run.llm_calls` records:
logical calls are distinct `(purpose, attempt)` pairs, transport
attempts are the flat record count, so retries are never
double-counted and never inflate the logical count. Cost is reported
only when both token counts are known and the model has a configured
price in the existing `PRICING_PER_MILLION`; otherwise
`estimated_cost_usd` is `null` (unknown, not zero, not free). In fake
mode tokens are unknown, so cost is `null` and
`missing_usage_rate` is reported explicitly. No pricing was invented
for M4; the pre-existing table is reused as-is.

### Ablations (offline, fake provider)

- **A — verifier diagnostics.** Deterministic-check verdicts are
  compared with the full deterministic+semantic verdicts on identical
  normally-executed runs. Diagnostic read only: no verification is
  disabled on any mutating path. Result at the M4 candidate run:
  18/18 comparable cases agree; the remaining runs end before a
  verification report exists (planning/policy failures).
- **B — retrieval context on/off.** Identical cases with the advisory
  retriever wired vs omitted (M1 wiring); policy, approval and
  verification are unchanged in both. Result: 23/24 terminal statuses
  consistent. The single difference,
  `mandatory_evidence_workflow_completes_with_citations`, correctly
  FAILS without a retriever because no canonical evidence can be
  attached — the mandatory gate failing closed, not a regression.
  Mean evidence spans per case drop from with-retriever to 0 without.

Both are fake-provider pipeline diagnostics. They do not establish
real model accuracy; the semantic reviewer is scripted in fake mode.

## Limitations and deferred items

- Trace spans are derived from audit events (stage-level), not
  fine-grained in-engine spans; no OpenTelemetry/Langfuse (optional
  per kickoff, no immediate benefit offline).
- Live-model evaluation and real Meta pricing are out of scope and
  require explicit approval for paid calls.
- Latency numbers are single-machine fake-mode timings for regression
  comparison only.
- Generated artifacts under `artifacts/` are git-ignored; the
  reproducibility manifest records the dataset/verdict digests.
