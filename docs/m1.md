# TrustFlow M1 — Real Meta Intelligence

## Fake / live switch (the only switch)

| Setting | Value | Behaviour |
|---|---|---|
| `TRUSTFLOW_LLM_MODE` | `fake` (default) | Deterministic `FakeLLMProvider`. Offline, zero cost. Tests and demo. |
| `TRUSTFLOW_LLM_MODE` | `live` | `MetaResponsesProvider` against the Meta Responses API. Requires `MODEL_API_KEY`. Any live failure raises and the workflow fails closed. **Never** falls back to Fake. |

Keys: TrustFlow reads `MODEL_API_KEY` (fallback: legacy `TRUSTFLOW_LLM_API_KEY`).
Muse's `META_API_KEY` is not read implicitly. Keys are never logged,
persisted, or included in reports; `/health` exposes only mode and model names.

Models: planning + independent semantic review use `muse-wonder-1.0`
(`TRUSTFLOW_PLANNING_MODEL`, `TRUSTFLOW_REVIEW_MODEL`); `muse-spark-1.3`
(`TRUSTFLOW_FAST_MODEL`) is available for lower-cost inference. Base URL
default `https://api.meta.ai/v1`, endpoint `/responses`, structured output via
`text.format` with flat, non-recursive schemas (recursive schemas return
HTTP 400 per official docs). Parameters verified at
https://dev.meta.ai/docs/structured-output and
https://dev.meta.ai/docs/pricing-rate-limits.

## Safety invariants added in M1

- Plans are validated (tool allowlist, Pydantic arg schemas, deterministic
  preconditions: known synthetic accounts, no self-transfer). At most **one**
  schema-repair attempt, then the workflow fails closed.
- Approvals are atomic in-process (lock around validate+record+transition),
  bound to plan version + SHA-256 hash over normalized executable args and
  stable `operation_id`s; replays are rejected.
- A committed transfer can never repeat: mutating steps carry a stable
  `operation_id` (run + parties + currency, independent of plan version and
  step id); the ledger is idempotent per key, the executor skips committed
  operations, timeouts reconcile against the ledger, and the verifier checks
  the executed amount against the approved plan amount.
- Semantic review (Wonder) receives the goal, the approved plan, and ledger
  evidence read independently from the ledger. It can only add failures;
  deterministic policy/verification remain authoritative.

## Budgets, retries, cost

Raw `httpx` (no SDK), so there is exactly one retry layer:
`1 + TRUSTFLOW_LLM_MAX_RETRIES` attempts, backoff on 429/5xx/transport errors,
per-call timeout `TRUSTFLOW_LLM_TIMEOUT_SECONDS`, output cap
`TRUSTFLOW_MAX_OUTPUT_TOKENS`, per-workflow token budget
`TRUSTFLOW_TOKEN_BUDGET_PER_WORKFLOW` (exceeding fails closed). Every call is
recorded on the run (`llm_calls`: model, request ID, latency, tokens, estimated
USD cost at official standard rates: Wonder $4/$20, Spark $1.25/$4.25 per 1M).
`expense_category` is always `application_inference`; Muse coding-agent
expenses are a separate subscription and are never counted here.

## Evaluation

`tests/eval/test_scenarios.py` holds 22 synthetic scenarios (M4 target: 30+).
**Explicitly deferred to M2:** the policy-retrieval and evidence-span scenario
families from the Playbook (no retrieval corpus or span annotations exist in
M0/M1). M2 will add them with the retrieval layer; until then they are tracked
as an open Playbook gap, not silently dropped.
