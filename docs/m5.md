  accepted M4 commit `fe142e739d472c52128d69141d62dffd7c3759f9`

  live errors never fall back to fake output.

  evidence, not acceptance verdicts; every phase below names the
  independent evidence that closes it.

## Preserved architecture and safety invariants (all phases)

These M1–M4 contracts are not redesigned in M5:

- Risk is decided by the deterministic backend `PolicyEngine`, never by
  the LLM alone.
- Approvals are bound to an immutable plan version + SHA-256
  `plan_hash`; repeats/replays are rejected (HTTP 409). The approval
  decision + exact snapshot + `EXECUTING` are CAS-persisted before any
  execution.
- Mutating tools are idempotent (operation/idempotency key + ledger
  `UNIQUE` backstop); succeeded steps are never re-executed on
  retry/resume/restart.
- Restart recovery is verification-only (`VERIFICATION_PENDING`,
  `EXECUTION_UNCERTAIN` + reconcile from ledger evidence); recovery
  never executes tools, transfers or model calls.
- Semantic-review attempts and the per-workflow token budget survive
  restart; usage is isolated per workflow and failed calls are recorded.
- Secrets come only from the environment; approval token and API keys
  are never logged or persisted; error output is sanitized.
- The frontend renders backend state only (authoritative GETs); it
  never renders a transfer as successful unless backend evidence says so.

## Deployment topology (current, M3-era, revalidated in M5.1)

```text
Browser (127.0.0.1) ──► Next.js frontend :3000 (NEXT_PUBLIC_API_URL
                        baked at build: http://127.0.0.1:8000)
                    └──► FastAPI backend :8000 (uvicorn, single process)
                           ├─ TRUSTFLOW_LLM_MODE=fake (FakeLLMProvider)
                           ├─ TRUSTFLOW_DB_PATH=/data/trustflow.db
                           ├─ TRUSTFLOW_APPROVAL_TOKEN=<demo token>
                           └─ volume tf-data:/data (SQLite, WAL)
```

Exact local run commands:

```powershell
docker compose up --build          # Docker path (daemon required)
# open http://127.0.0.1:3000  (approval token: see docker-compose.yml)
```

Without Docker: backend with `TRUSTFLOW_DB_PATH` +
`TRUSTFLOW_APPROVAL_TOKEN` set, plus `npm run build` / `npm run start`
in `frontend/` (see README).

(with regression tests). No architecture rewrite, no PostgreSQL, no UI

Checks (all executed, not only inspected):

- `docker compose config` renders the expected two-service topology.
- Docker Compose build + startup (if the daemon is available; otherwise
  the exact blocker is reported and the local-process path below is
  executed instead — a Docker PASS is never claimed from inspection).

  `approval_auth_required=true`.

  verify flow against the backend API (browser-origin CORS honoured).

  must never be reused in a public deployment.

  restart; committed transfers are never duplicated after restart.
- Startup diagnostics: missing/invalid configuration fails loudly with
  a sanitized error; no credentials in logs or error responses.

Findings:

- **No P1 deployment blocker reproduced.** The Docker path works end
  to end from the committed files.
- **P2 hardening (fixed):** no `.dockerignore` existed, so the frontend
  build context shipped host `node_modules`/`.next` into the image
  build (`COPY . .` over the in-image `npm ci`). The build happened to
  succeed, but the context was huge and host-platform artifacts could
  break native binaries. Added `frontend/.dockerignore` and a root
  `.dockerignore`, guarded by `tests/api/test_m5_deployment.py`.
- **P2 docs (fixed):** `docs/m3.md` references
  `tests/api/test_m3_demo.py`, which does not exist in the tree (demo
  scenarios live in `tests/api/test_m3_api.py`). Noted here; M3 doc
  left untouched as historical evidence.
- **Demo finiteness (by design, M5.2 input):** the synthetic ledger has
  finite seed funds. Replaying `Transfer 5000` repeatedly against one
  volume eventually yields `Insufficient synthetic funds` → step
  `FAILED` → verification FAIL → bounded re-plan to
  `AWAITING_APPROVAL`, with no fabricated or duplicate transfer
  (observed live; ledger conservation held, `total=16200.0`). A
  documented seed/reset procedure is an M5.2 acceptance item above.
- The demo approval token remains a public local-demo value in
  `docker-compose.yml`; a warning comment now states it must never be
  reused in a public deployment.

Residual risks / not exercised: live Meta API (no paid calls, by
design); browser-driven UI click-through in this phase (API + CORS +
served-page evidence only; headless-Chrome UI verification exists from
M3); multi-instance/PostgreSQL (out of scope, single-instance demo).
